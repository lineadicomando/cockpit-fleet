## Assistant profiles (phase 12), as of 28 November 2026

Classes of commands enforced by the backend (`agent=`), five profiles the administrator enables (all of them as installed since 18 November, with the ceiling at admin; before, `observer` and `assisted` under operator); `administrator` only for an agent acting as admin (the user's role under the ceiling), held by the backend, not by Cockpit's administrative access, which it cannot see (18 November) and the user picks, that only restrict; ad-hoc free and code never autonomous; an agent's files on a draft branch a person merges, file by file, not line by line (a file changed in `main` too is a conflict); instructions in layers, not a control, refused rather than cut when the controller's file is too large or not UTF-8. Autonomy: a few runs a session, no launch on an inventory in maintenance, no `state.ack`/`unack` or `maintenance.*`. The limit stays, but the person allows more from the page when the runs are spent (`[chat] autonomous_runs` more each time), and "Stop everything" stops the answer and cancels the runs of the conversation not ended, in any profile; not no limit plus a stop button, which holds only while somebody watches (23 November). The user chooses the runs of each conversation when starting the session (lower or higher, no ceiling of the administrator's, since grants have none); 30 by default instead of 10 (23 November). A diagnostic ad-hoc command never waits; any other of an agent waits for its person; `approval.approve`/`reject` need the role operator or the right. Questions decided by the backend, one table (`profiles.question`) for the page and the terminal: none for reading, `run` in `autonomous` and diagnostic ad-hoc in `diagnostic`; every time for adhoc, config, code; else asked, "always" trusting a class for the conversation. The risks of `diagnostic`, `autonomous`, `administrator` accepted once by each user, recorded, and held by the backend (`chat.start` refuses). 5 and 6 November. A profile offered only to a role it does more for: `diagnostic` and `administrator` from admin, `assisted` and `autonomous` from operator, a viewer one profile (`observer`, else `assisted`), so that no one accepts risks of powers the role does not give (a review of the profiles, 28 November). `autonomous` a profile no more but "Without questions" in `assisted`, as the switch of `administrator`: the same classes, so a mode of the session (`[chat] autonomous`, on by default) that turns on and off without starting the agent again, the limits of autonomy unchanged and its acceptance kept; every launch of the conversation counted, those confirmed before included; not at a terminal (`fleet assistant --profile autonomous` refused); the audit records the mode beside the profile; `autonomous` in `[chat] profiles` and for `fleet-mcp` by hand read as that mode, deprecated (28 November)
